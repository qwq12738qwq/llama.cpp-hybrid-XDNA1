# Tile-Order Forensics: Hypothesis

## Original Hypothesis

> When N_div_n > 1, the order of B tiles generated by TensorTiler2D/TAS does not match the order in which the AIE core acquires B objects and invokes matmul(A_tile, B_tile, C_tile).

## Refined Hypothesis After Investigation

The root cause is a **mismatch between the B tensor's L3L2 DMA stream order and the core's acquire order**:

1. **Core acquire order** (from core_fn loop structure):
   ```python
   for tile_row in range(M // m):
       for tile_col in range(N // n):
           for k_tile in range(K // k):
               acquire A, acquire B, matmul
   ```
   → N-outer, K-inner (for each output tile column, stream all K tiles)

2. **Buggy TAS order** (row-major for K>512):
   → K-outer, N-inner (streams all K tiles for N=0, then all K tiles for N=1, etc.)

3. **Fix**: Keep col-major TAS (N-outer, K-inner) for L2L1, but split L3L2 into per-N-column BDs when K*N > 64KB.

## Verification Methods

- **B-Tile Identity Experiment**: Unique tile IDs in B matrix → decode output to infer acquire sequence ✓
- **A-Tile Identity Experiment**: Not needed (A was correct)  
- **C-Tile Identity Experiment**: Not needed (C drain was correct)
- **TAS vs BD Comparison**: Confirmed TAS order propagates to BD ✓
- **BD vs Core Comparison**: Confirmed mismatch with row-major TAS ✓

## Status: CONFIRMED — Root cause is A (TAS generation order wrong for K>512)
